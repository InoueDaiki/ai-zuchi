# 検証: オーバーレイ

オーバーレイの OS に依存する振る舞いの確認手順。**画面共有からの除外とフォーカスは、どれも未検証。** 実機で確かめ、結果を下の表に書く。

## 準備

```bash
# 4 秒ごとに偽の補足を流す。メニューの「偽の補足を出す(開発用)」でも 1 件ずつ出せる
ZUCHI_FAKE_INTERVAL_SECS=4 mise run dev
```

偽の補足は開発のビルドにだけ含まれる。実際の会議で確かめるときも、共有してよい内容しか出ない。

配布の形でも結果が同じとは限らないので、最後に `pnpm --filter desktop tauri build` の成果物でも見る。

## 確認済み

2026-11-01、macOS の開発機で `tauri dev` を起動し、`CGWindowListCopyWindowInfo` とログから確かめた。画面はロック中とみられ、撮影できなかった。人の目では見ていない。

- ウィンドウが右上の作業領域に 360 ポイント幅で置かれ、カードの高さに縮む(メニューバーの下、Y=39)
- ウィンドウのレベルが 5 で、通常のウィンドウ(0)より手前にある
- `kCGWindowSharingState` が 0(`NSWindowSharingNone`)になっている。**これは指定が通った確認であって、画面共有に映らないことの確認ではない**
- 補足のイベントが画面に届き、消えると Rust 側に `Ignored` の反応が届く

## 画面共有に映らないこと

カードを出したまま共有し、**別の端末の受信側で**見る。送信側のプレビューは当てにしない。

| 対象 | 手順 | 映らない | 備考 |
|---|---|---|---|
| Zoom(macOS) | 画面全体を共有 | 未検証 | |
| Zoom(macOS) | ウィンドウを共有 | 未検証 | |
| Google Meet(Chrome、macOS) | 画面全体を共有 | 未検証 | |
| Microsoft Teams(macOS) | 画面全体を共有 | 未検証 | |
| QuickTime の画面収録(macOS) | 画面全体を録画 | 未検証 | |
| `screencapture`(macOS) | `screencapture -x /tmp/a.png` | 未検証 | |
| Zoom(Windows 11) | 画面全体を共有 | 未検証 | |
| Google Meet(Windows 11) | 画面全体を共有 | 未検証 | |
| Teams(Windows 11) | 画面全体を共有 | 未検証 | |
| Snipping Tool(Windows 11) | 全画面の切り取り | 未検証 | |

見ておく点。

- **macOS:** `NSWindow.sharingType = .none` は、ScreenCaptureKit を使う新しい取得では効かないとの報告がある。macOS の版を表に残す。効かない場合、OS の API だけでは防げないと考える
- **Windows:** `WDA_EXCLUDEFROMCAPTURE` は Windows 10 2004 以降。対象の Windows 11 では使えるはずだが、ハードウェアアクセラレーションの有無で変わらないかも見る
- **全般:** スマートフォンでの撮影や HDMI の出力先は防げない。プロジェクターなどへの拡張表示では、カードは主画面にしか出ない
- **防げなかったとき:** 会議のアプリを検知してカードを控えめにする、などを検討する。それまでは「映るかもしれない」前提で使う

## フォーカスを奪わないこと

文字を入力しているアプリを前面にして確かめる。

| 確認 | macOS | Windows |
|---|---|---|
| 起動しても入力中のアプリのフォーカスが移らない | 未検証 | 未検証 |
| カードが出ても入力が途切れない | 未検証 | 未検証 |
| カードのボタンを押しても入力先が変わらない | 未検証 | 未検証 |
| カードのボタンが 1 回のクリックで効く(`acceptFirstMouse`) | 未検証 | 未検証 |
| カードにカーソルを載せると消えるまでの時間が止まる | 未検証 | 未検証 |

`focusable: false` は macOS では `canBecomeKeyWindow` を偽にする指定で、ウィンドウが通常の `NSWindow` のままなので、**クリックでアプリが有効化される可能性がある**。問題があれば `NSPanel`(`nonactivatingPanel`)に変える。Windows は `WS_EX_NOACTIVATE` の相当。

## クリックが背後へ抜けること

| 確認 | macOS | Windows |
|---|---|---|
| カードがないとき、右上のウィンドウの閉じるボタンなどを押せる | 未検証 | 未検証 |
| カードが消えた直後に、元の位置のものを押せる | 未検証 | 未検証 |

カードの周りの 6 ポイントの透明な余白はクリックを受ける。影を切らないための余白で、気になれば縮める。
